Building Software with Agents

A self-paced course on directing coding agents to build and ship full-stack web apps, at about one module per week

Coding agents can write most of the code in a project, so a developer is now hired for judgment, which means deciding what to build, setting the constraints, and checking the result. In this course you build the same projects as the GSG Code Academy track, but an agent writes the code and you design, constrain, review and fix it.

How each module is organised

Every module has the same four strands. The strands follow the GSG curriculum weeks, so each module ends with the project from the matching GSG week.

StrandWhat you learn
Systems modelHow the parts around your code work, e.g., the browser, the server, the database and the network between them. You learn enough to read the evidence an agent produces and to notice when it fixes the wrong part. You read the output of tools, and you don't memorise how to run them.
Build, then buyYou build a small version of a feature once so you understand it, and then you replace it with a library or a service. You write down why in a short decision record.
Agent craftOne way that agents fail, and the guardrail that prevents it. The guardrails live in the repo, e.g., AGENTS.md, tests and git, so they work with Claude Code, Codex, opencode, pi and Amp.
ProjectThe GSG project for that week. You write the spec, and an agent writes the code. You then review the code, try to break it and fix what fails. You hand in your spec, your AGENTS.md, your decision records and your review notes to your mentor.

Modules

Module 0. How coding agents work and how to direct them

Agent craft. No GSG week; complete it before everything else.

  1. An agent is a model, a set of tools and a loop
  2. Directing one agent session from plan to proof
  3. Keeping project knowledge in the repo and in saved sessions
  4. Learning a new library with an agent, from its docs and source

Module 1. How browsers, servers and APIs talk over HTTP

Follows GSG weeks 1 and 3. Project: a single-page app that uses two public APIs.

  1. Reading one request across five systems
  2. HTTP methods, status codes and headers
  3. Why the browser blocks some requests, with same-origin and CORS
  4. Deciding whether to build, buy or self-host, starting with fetch
  5. Project: a single-page app from two public APIs, built by an agent

Module 2. Servers, configuration and the Twelve-Factor App

Follows GSG weeks 4 and 5. Project: a news app that calls an API from the server.

A server is a process that listens on a port, and you'll build a small one with Node's http module before you move to Express or Hono. The Twelve-Factor App is the main reference for this module, and it explains how to keep configuration in the environment so you can run several copies of an app on one laptop. On the agent side, you learn to write specs with acceptance criteria and to keep diffs small.

Module 3. Databases as separate services, and tests as the contract

Follows GSG week 6. Project: an Express app with PostgreSQL.

You start with raw SQL and then move to a query builder such as Drizzle, and you learn about schemas, migrations, test databases and SQL injection. On the agent side, you learn how agents weaken or fake tests, and how linters, CI and git hooks stop destructive commands and unchecked changes.

Module 4. Identity, sessions and security review of agent code

Follows GSG week 7. Project: a site with authentication.

You write a 60-line cookie session by hand, and then you replace it with better-auth and compare the two. You also compare better-auth with hosted and self-hosted options. On the agent side, you learn about prompt injection, the "lethal trifecta" described by Simon Willison, and how secrets leak into an agent's context.

Module 5. Front-end architecture and learning new tools quickly

Follows GSG weeks 9 and 11. Project: a React front end for your own API.

You learn what the browser downloads and where the boundary between client and server sits, and you compare hand-written CSS with Tailwind and a component library. On the agent side, you learn to use TypeScript as a constraint and to split work across subagents and git worktrees.

Module 6. Capstone: a full-stack e-commerce app

Follows GSG week 10. Project: the e-commerce app, deployed.

You run the whole set of guardrails from earlier modules on one large project, with several agents working in parallel on your laptop. You finish with a list of every build, buy and self-host decision you made, and with a written account of the project for your portfolio and for interviews.

Reference sheets

These sheets are for looking things up, and you don't need to read them in order.

  • Glossary, which holds the terms every lesson uses
  • Agent session checklist, which covers how to start, direct, check and end a session
  • Agent failure catalog, which grows in every module and lists each failure with its symptom, cause and guardrail
  • Reading HTTP evidence, which explains curl -v output, status codes and which part failed
  • Decision record template, for build, buy or self-host choices
