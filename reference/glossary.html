Glossary

The terms used across the course. Lessons use these words with these meanings. The last column links the lesson that introduces each term.

TermMeaningLesson
Acceptance criteriaTestable conditions that a user story must meet before it counts as done.9
AGENTS.mdA Markdown file in a repo that tells coding agents how to work in it, e.g., the build and test commands, the conventions and the limits.3
CompactionA tool replaces older messages in the context with a summary, so the session can continue when the context is nearly full.3
Context rotThe model recalls information from its context less accurately as the context gets longer (Anthropic).1
Context windowAll the text sent to the model on one request, i.e., the instructions, the tool list and the conversation so far.1
CORSCross-Origin Resource Sharing, a set of response headers that tell the browser which other origins may read a server's responses.7
Decision recordA short Markdown file in the repo that says what was decided, which options were compared, and why.8
DependencyA package that your project installs from npm and needs in order to run.8
Directed promptA prompt that gives the goal, the files, the design, the edge cases with tests, the limits and the proof required.2
DNSDomain Name System, the directory that turns a name such as example.com into an IP address.5
Handoff noteA short note with the goal, decisions, files and open questions, written so that a new session can continue the work.3
HeaderA name and value pair sent before the body of a request or response, describing the body, the client or caching rules.6
Hosted serviceA program that a company runs on its servers and that your app calls, paid for with money or a limited free tier.8
Idempotent methodA method where sending the same request several times has the same intended effect as sending it once, e.g., PUT and DELETE.6
LLMLarge language model, the kind of model behind coding agents.1
llms.txtA Markdown index of a documentation site, written for language models to read.4
MethodThe word at the start of a request, e.g., GET or POST, that says what action the client asks for.6
OriginThe scheme, host and port of a URL together, e.g., https://example.com:443.7
Preflight requestAn OPTIONS request that the browser sends before a cross-origin request that isn't simple, to ask whether the real request is allowed.7
Safe methodA method where the client asks only to read and expects no change on the server, e.g., GET and HEAD.6
Same-origin policyA browser rule that stops JavaScript on one origin from reading responses from another origin, unless that origin allows it with CORS.7
Self-hosted serviceA separate program that you install and run on your own server, and that your app talks to over HTTP.8
Session trailerA Session: line at the end of a commit message that points to the saved transcript of the agent session behind the commit.3
SpikeA small throwaway program, kept outside the project, that answers one question about a library.4
Static siteA site made only of HTML, CSS and JavaScript files, with no server code, so anyone can read every published file.9
Status codeThe three-digit number in a response. Its first digit gives its class, from 1xx to 5xx.6
TCPTransmission Control Protocol, which opens a reliable connection to an IP address and port. The connection starts with a three-message handshake.5
TLSTransport Layer Security, which checks the server's certificate and encrypts the connection. HTTPS is HTTP over TLS.5
Tool callA structured request in the model's reply that names a tool and its input. The agent program runs the tool, and the model doesn't.1
Tool resultThe output of a tool that the agent program ran, added to the context for the next model request.1
Training cutoffThe date after which the model saw no new data, so it doesn't know later changes to a library unless they are put in its context.4
Weekly downloadsThe number of times npm served a package in one week, including automated builds, so it overstates the number of users.8
