Agent failure catalog

Each row is a way coding agents fail, with the symptom you see, the cause and the guardrail that prevents it. New modules add rows. You can use the rows as material for interview answers.

Module 0: directing agents

FailureSymptomCauseGuardrailLesson
Claims without proofThe agent says "all tests pass" and shows no output.The model's text isn't backed by a tool result.Ask for test output or a command you can rerun, and then rerun it yourself.2
Polluted long sessionThe agent repeats failed fixes, or old behaviour leaks into new work.Failed attempts and unrelated tasks build up in the context.Use one task per session, and restart with a short handoff note.1
Self-review biasThe session that wrote the code approves its own diff.Its context holds its own reasoning for every choice.Review git diff in a fresh session, and judge each finding yourself.2
Instructions silently ignoredClaude Code doesn't follow AGENTS.md.A CLAUDE.md in the working directory or a parent directory takes precedence.Check for the "AGENTS.md loaded" line at session start, and remove stray CLAUDE.md files.3
Lost contextA new session redoes or contradicts earlier decisions.Every session starts with an empty context.Write commit messages that say why, save transcripts, and write handoff notes.3
Secret committed in a transcriptCredentials appear in a saved session transcript.Transcripts capture tool output, including printed secrets.Read a transcript before you commit it, and use the tool's sanitize option where it has one.3
Outdated APIThe agent uses an option that the installed version removed or renamed.The model learned an older version before its training cutoff.Point the agent at the installed readme and type definitions, and ask it to quote them.4
Invented APIThe agent calls a method that doesn't exist, e.g., ky.fetchJson().The model generates a plausible name.Search the installed type definitions for the name before you accept the code.4

Module 1: HTTP and the browser

FailureSymptomCauseGuardrailLesson
Disabled certificate checkA TLS error disappears after the agent adds -k or NODE_TLS_REJECT_UNAUTHORIZED=0.The agent turned off the check instead of fixing the certificate or host name.Reject any change that disables verification, and fix the cause.5
Fix on the wrong systemThe agent edits route code after a TCP connection error.The agent didn't read which system failed.Read the error number first, e.g., error 7 means nothing is listening.5
Retries on POSTDuplicate orders or charges appear.POST isn't idempotent, so a retry repeats the action.Allow automatic retries only on idempotent methods.6
Error sent with status 200The front end treats failures as success.The status line and the body disagree.Require the status to match the result, and check response.ok.6
Hand-parsed JSON bodyThe agent works around an empty req.body by parsing the body manually.The client didn't send a Content-Type header.Fix the header instead of the parser.6
Wildcard CORS with cookiesThe browser still blocks the response after the agent adds Access-Control-Allow-Origin: *.The wildcard is forbidden when the request carries credentials.Name the exact origin and add Access-Control-Allow-Credentials: true.7
CORS header on the wrong serverThe agent adds the header, and nothing changes.The header must come from the server that the browser reads from.Check in the Network tab which response is blocked.7
Disabled browser security or public CORS proxyThe app works only on one machine, or it sends keys through a stranger's server.The error is hidden, not fixed.Call the third-party API from your own server (Module 2).7
curl used as proof of a CORS fixThe agent says "curl works, so CORS is fixed".curl ignores CORS, which only the browser enforces.Prove it in the browser, or show the header in curl -i output.7
Unasked dependencyA new package appears in package.json for a small problem.Agents install packages by default.Add an AGENTS.md rule to ask first and show the signals, and write a decision record.8
Wrong or invented package nameThe install succeeds, but the npm page links to an unexpected repo.The model guessed a package name.Check the npm page and repo link before you approve the install.8
Unchecked fetch()The code continues with an error body after a 404 or 500.fetch() doesn't reject on HTTP error statuses.Use a wrapper or ky, and check for response.ok in review.8
API key in front-end codeA key string appears in app.js or in git history.The agent copied the docs example directly into browser code.Add an AGENTS.md rule, search with git log -p, and revoke any key that leaked.9
Weakened testAn assertion such as toBe(3) becomes toBeDefined().The agent made the test pass instead of fixing the code.Add an AGENTS.md rule, and read test changes in a fresh-session review.9
Invented endpointThe code calls a path that isn't in the API docs.The model guessed a plausible URL.Add an AGENTS.md rule to use only documented endpoints, and check each one.9
