The five systems a request passes through

OrderSystemWhat it doesWhere you see it in curl -v
1DNSTurns a name into an IP address* Host ... was resolved, then the IPv4 and IPv6 lines
2TCPOpens a connection to an IP address and port* Trying ... and * Established connection
3TLSChecks the certificate and encrypts the connection* TLSv1.3 ... handshake and * Server certificate:
4HTTPCarries the request and the responseLines starting with > (sent) and < (received)
5ApplicationServer code that decides the responseThe status code and the body

In curl -v output, * marks a note from curl, > marks a header that curl sent, < marks a header that curl received, and { or } marks raw data (man curl, --verbose). Timings from -w count from the start of the request, so you subtract the previous value to get one step's time.

Methods

MethodUsual meaningSafeIdempotent
GETRead a resourceYesYes
POSTCreate something or submit dataNoNo
PUTReplace a resourceNoYes
PATCHChange part of a resourceNoNo
DELETERemove a resourceNoYes

A safe method asks only to read. With an idempotent method, sending the same request twice has the same intended effect as sending it once, so you may retry it after a failure. Automatic retries on POST can create duplicate orders or charges. Sources: RFC 9110, section 9.2, and RFC 5789 for PATCH.

Status codes

ClassMeaningNext step
2xxSuccessUse the response.
3xxRedirectionFollow the Location header.
4xxClient errorChange the request, because the same request gets the same answer.
5xxServer errorLook at the server. A retry may help if the failure was temporary.

401UnauthorizedThe request has no valid credentials.
403ForbiddenThe credentials don't allow this action.

405Method Not AllowedThe path doesn't accept this method.
429Too Many RequestsYou hit a rate limit.
500Internal Server ErrorThe server's code failed.
503Service UnavailableThe server is overloaded or down.

fetch() rejects its promise only when the network fails, so for a 404 or a 500 your code has to check response.ok (MDN, Using the Fetch API). A response with status 200 and an error message in the body is a defect, because clients trust the status code.

HeaderSent byWhat it says

CORS errors in the browser console

The messages below were captured in Chromium 151. Only the browser enforces CORS, and curl ignores it, so a working curl request is not proof that CORS is fixed.

Console message containsMeaning
No 'Access-Control-Allow-Origin' header is presentThe API sent no CORS header, so the browser hid the response from your script.
Response to preflight request doesn't pass access control checkThe browser's OPTIONS request failed, so it never sent the real request.
must not be the wildcard '*' when the request's credentials mode is 'include'The API answered with *, but the request carried cookies, which the browser forbids.
Access-Control-Allow-Credentials ... must be 'true'The API named your origin but didn't allow credentials.

A third-party API that sends no CORS headers can't be fixed from the browser. Call it from your own server instead, which Module 2 covers. Source: MDN, CORS.
